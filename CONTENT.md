# DataDoodles Landing Page Design Prompt

Design a high-converting landing page for **DataDoodles**, a service that helps businesses become more visible and recommended across ChatGPT, Google AI Overview, Gemini and Perplexity.

The page should feel premium, technical, trustworthy and modern. It must look like a serious AI-search consultancy rather than a typical digital-marketing agency.

Use the copy provided separately. Focus on visual hierarchy, conversion flow, evidence presentation and mobile responsiveness.

---

## Core visual direction

Create a **Precision GEO** visual system built around:

- Calm near-white backgrounds
- Deep Onyx structure
- Strong editorial typography
- Technical grid alignment
- Dark evidence panels
- Carefully controlled Signal Red accents
- Measured data labels
- Clean lines instead of decorative graphics

The visual mood should communicate:

- Precision
- Authority
- Measurable results
- Modern AI expertise
- Transparency
- Premium consultancy

Avoid making the page feel overly corporate, futuristic, neon, playful or filled with generic AI illustrations.

---

## Colour palette

Use these colours consistently:

- Paper: `#FDFCFB`
- Surface: `#FFFFFF`
- Surface low: `#F4F3F2`
- Surface container: `#EEEEED`
- Deep Onyx: `#2F3130`
- Darker Onyx: `#1A1C1C`
- Ink: `#111111`
- Body ink: `#1A1C1C`
- Muted: `#444748`
- Data gray: `#666666`
- Rule: `#C4C7C7`
- Rule light: `#E5E5E5`
- Signal Red: `#E21E35`
- Signal Red hover: `#BB0024`
- WhatsApp: `#25D366`
- Error: `#BA1A1A`
- Inverse text: `#F1F0F0`

The page should contain a healthy balance of light and dark sections.

Use Deep Onyx for:

- Evidence sections
- Case-study containers
- Key comparison areas
- Selected process sections
- Final CTA section
- Important proof summaries
- Data-heavy content blocks

Signal Red should be visible throughout the page, but used with discipline.

Use it for:

- H1 underline
- Small section markers
- Recommended-result labels
- Case-study performance figures
- Active tabs
- Form focus states
- Thin borders
- Small squares within the background grid
- Selected icon details
- Timeline progress
- Hover states

Do not use Signal Red as a large full-section background.

---

## Typography

Use:

- **Manrope** for headings, body copy, buttons and navigation
- **JetBrains Mono** for:
  - Section labels
  - Platform names
  - Dates
  - Search queries
  - Result types
  - Statistics
  - Verification labels
  - Small technical captions

Headings should have strong weight contrast and tight tracking.

Do not go below `-0.04em` letter spacing.

Narrative paragraphs should stay under approximately 70 characters per line.

Use generous type sizing:

- Hero H1: 64–80px desktop
- Section headings: 42–56px desktop
- Subheadings: 24–32px
- Body: 17–19px
- Mono labels: 11–13px uppercase

---

## Layout system

Use a 12-column desktop grid.

- Maximum width: `1280px`
- Desktop outer margins: `64px`
- Tablet margins: `32px`
- Mobile margins: `16px`
- Base spacing rhythm: `8px`
- Corner radius: `4px`
- Section spacing should be consistent throughout

Use strong column alignment and visible rules.

Each section should open with:

1. A JetBrains Mono label
2. A horizontal 1px rule
3. A two-digit section index

Example:

`AI VISIBILITY` ————————————— `02`

Use this device consistently throughout the page.

Most sections should stay inside the main grid.

Allow only selected sections to become full bleed:

- Hero marquee
- Search-behaviour shift section
- Case-study showcase
- Final CTA

# Page structure

## 1. Header

Create a minimal sticky header.

Left:

- DataDoodles wordmark

Centre or right:

- How It Works
- Results
- Why AI Visibility
- FAQ

Primary button:

**Check My AI Visibility**

The header should begin transparent or Paper-coloured and gain a subtle bottom border on scroll.

Do not use a large floating navigation container.

---

## 2. Hero section

Use a 7-column copy area and 5-column interactive exhibit.

### Left side

Include:

- Mono eyebrow:
  `GEO / AI SEARCH VISIBILITY`
- Large headline:
  **Become the Business AI Recommends**
- Underline the phrase **AI Recommends** using Signal Red
- Supporting paragraph
- Primary CTA
- Secondary text link
- Three short proof claims beneath

Example proof claims:

- 30-day implementation
- Multi-platform visibility
- Real point-in-time proof

Use JetBrains Mono for the proof claims.

### Right side

Build a dark interactive **AI recommendation exhibit**.

The exhibit should resemble a clean AI-search interface, but not copy any specific product exactly.

Use:

- Deep Onyx container
- White or light response areas
- A centred title:
  `AI OVERVIEW`
- One customer question
- Several AI-generated recommendation rows
- A Signal Red outlined label marking:
  `YOUR BUSINESS`
- A date and platform bar at the top
- A small verification caption at the bottom

The interface should show the user asking:

> “Which company should I choose?”

Then show several recommendations, with “Your Business” appearing as the highlighted recommended result.

The dark exhibit should be visually substantial and immediately communicate the service.

---

## 3. Hero marquee

Create a full-width dark marquee directly beneath the hero.

Use two horizontal strips.

Top strip:

**GEO / AEO / SEO / AI VISIBILITY / AI RECOMMENDATIONS**

Bottom strip:

**BE FOUND / BE UNDERSTOOD / BE RECOMMENDED**

Use Manrope for the upper strip and JetBrains Mono for the lower strip.

Include small Signal Red squares between phrases.

Keep the movement slow and subtle.

---

## 4. Search behaviour shift section

Make this a full-width Deep Onyx section.

Use a two-column layout.

### Left

Large editorial statement:

**Customers are no longer only searching. They are asking AI who to choose.**

### Right

Show a comparison between traditional search and AI search.

Use two stacked dark-to-light comparison panels.

Traditional search:

- Ten blue links
- Multiple websites
- Manual comparison
- More effort

AI search:

- Direct recommendation
- Shortlist of companies
- Reasons to choose
- Faster decision

Use Signal Red only to mark the recommended company in the AI-search side.

## 8. Case-study proof section

This is one of the most important sections.

Use a mixture of dark evidence containers and light text areas.

Heading:

**Real Businesses. Real AI Visibility.**

Supporting text:

Show genuine point-in-time examples from ChatGPT, Gemini, Perplexity and Google AI Overview.

### Case-study layout

Do not place all six cases inside small equal cards.

Use a magazine-style evidence grid.

Create:

- Two large featured case studies
- Four smaller supporting cases

Featured cases:

1. Singapore Funeral Group
2. Ang Brothers Funeral Services

Supporting cases:

3. Four Solutions
4. Nook Nook
5. Advanced Consultancy
6. Korean Explorer

### Featured case-study construction

Each feature should include:

- Company name
- Industry
- Platform tags
- Large result statement
- One cropped screenshot
- Search query
- Verification date
- Result type
- View Proof action

Use a Deep Onyx frame around screenshots.

Inside the screenshot, mark the recommended business with a thin Signal Red border and label.

Do not place red graphics over text.

### Supporting case studies

Use dark rectangular evidence cards separated by rules.

Each should show:

- Company
- Platform
- Result
- Small cropped proof image
- Verification label
- “View full result”

Use Signal Red only for the result label or figure.

### Screenshot treatment

Screenshots must be cropped tightly to show:

- Search question
- Company name
- Recommendation
- Website citation
- AI platform identity

Remove:

- Browser tabs
- Large blank spaces
- Side menus
- Taskbars
- Irrelevant answer text

Use a lightbox when users select “View Proof”.

The lightbox should show:

- Larger screenshot
- Exact query
- Platform
- Date verified
- Short explanation
- Point-in-time disclaimer

# Background treatment

Use a fixed technical grid behind the page.

Grid size:

- 26px desktop
- 22px mobile

The grid should be extremely subtle.

A small irregular group of cells may react gently to pointer movement.

Scatter a limited number of deterministic Signal Red squares throughout the grid.

Do not allow background effects to reduce text contrast.

Disable the effect under reduced-motion settings.

---

# Dark-section balance

Approximately 35–45% of the page should use dark surfaces.

Recommended dark areas:

- Hero evidence exhibit
- Hero marquee
- Search-behaviour shift
- Proof summary
- Selected case-study containers
- Benefits cards
- SEO comparison
- Lead-generation section
- Final CTA
- Footer

Avoid making every section dark. Alternate dark and light carefully so the page retains visual rhythm and does not become heavy.

---

# Card treatment

Although the system is primarily editorial, use rectangular cards where they help organise evidence and benefits.

Cards must follow these rules:

- 1px borders
- 4px corners
- No shadows
- No floating appearance
- No large rounded corners
- No decorative gradients
- Strong alignment
- Dark or white backgrounds
- Clear internal spacing
- Thin rules between content areas

Cards should feel like technical exhibits or published data blocks rather than SaaS dashboard widgets.

---

# Motion

Use restrained, purposeful motion.

### Hero entrance

Sequence:

1. Mono kicker
2. Lead form or CTA
3. Headline rising word by word
4. Supporting copy
5. Proof claims
6. Signal Red underline
7. Recommendation label inside the evidence exhibit

Total duration should be approximately one second.

### Scroll reveals

Use:

- Opacity transition
- 12px upward movement
- 400ms duration
- One-time reveal
- 70ms stagger between same-row items

### Interactions

Keep user-triggered animation between 120–200ms.

### Do not use

- Typewriter effects
- Counting numbers
- Parallax
- Scroll-jacking
- Delayed content
- Decorative 3D objects
- Floating AI icons

---

# Pointer behaviour

On desktop fine-pointer devices:

- 6px Signal Red pointer dot
- 30px Onyx tracking ring
- Ring expands over links and buttons
- Ring turns Signal Red over interactive controls
- Custom pointer hides over text inputs

Keep native pointer on:

- Touch devices
- Reduced-motion settings
- Text-entry fields

---

# Mobile design

The mobile design must remain conversion-focused.

Requirements:

- Single-column content
- Large readable headings
- Proof screenshots remain legible
- Case-study evidence can swipe horizontally
- Timeline becomes vertical
- Comparison sections stack
- Form takes full width
- Sticky action bar appears after the hero
- Sticky bar reserves page space and never covers content

Sticky actions:

- Primary: Check My AI Visibility
- Secondary: WhatsApp icon

Use WhatsApp green only on the WhatsApp system action.

---

# Accessibility

Ensure:

- Minimum 4.5:1 text contrast
- Visible keyboard focus
- Native form labels
- Reduced-motion support
- Logical heading hierarchy
- Accessible lightbox controls
- Descriptive screenshot captions
- No information communicated through colour alone
- Touch targets at least 44px high

---

# Final design objective

The finished landing page should feel like a combination of:

- A premium consultancy website
- A technical research publication
- A measurable AI-search report
- A conversion-focused service page

It should not feel like:

- A generic SEO agency
- A colourful startup template
- A cyberpunk AI company
- A card-heavy SaaS dashboard
- A page filled with decorative technology graphics

The strongest visual impression should be:

> **DataDoodles measures how AI sees your business and helps improve your chance of becoming the recommended answer.**
